# Releasing

Releases are built by GitHub Actions ([`.github/workflows/release.yml`](../.github/workflows/release.yml)) on a `windows-latest` runner. Each release contains:

| Asset | Contents |
|---|---|
| `mfe-launcher.exe` | The launcher, with its file and product version stamped from the release version |
| `SHA256SUMS.txt` | The SHA-256 checksum of the exe |

The release notes are generated by GitHub from the commits and pull requests since the previous release. The same two files are also kept as a workflow artifact on the run.

## Publish a release from a tag

```powershell
git tag v1.2.0
git push origin v1.2.0
```

Pushing a tag that matches `v*.*.*` starts the workflow, which then:

1. reads the version from the tag (`v1.2.0` → `1.2.0`);
2. runs `./build.ps1 -Version 1.2.0`;
3. writes `SHA256SUMS.txt`;
4. creates the **published** release `v1.2.0`, titled *MFE Launcher v1.2.0*, with both files attached.

## Run it by hand (draft)

1. Open the **Actions** tab, then **Release**, then **Run workflow**.
2. Enter a version, such as `1.2.0`. Leave **Create the release as a draft** ticked to review the release first.
3. When the run finishes, open **Releases**, check the draft, and click **Publish release**. GitHub creates the `v1.2.0` tag on the commit the workflow built when you publish.

Untick **draft** to publish straight away.

## Versioning

Use [semantic versioning](https://semver.org/) in the form `MAJOR.MINOR.PATCH`. The workflow rejects anything else. The version only labels the build: nothing in the repo needs to change before you release.

To stamp a local build the same way:

```powershell
.\build.ps1 -Version 1.2.0
(Get-Item .\dist\mfe-launcher.exe).VersionInfo.FileVersion   # 1.2.0.0
```

## Notes

- The workflow needs `contents: write` permission to create releases. It's declared in the workflow file, so no repository settings need to change.
- A release fails if its tag already has a release. Delete the old release, or use a new version.
- The exe isn't code-signed, so Windows SmartScreen warns on first run. See [Troubleshooting](troubleshooting.md#windows-smartscreen-blocks-the-exe).
